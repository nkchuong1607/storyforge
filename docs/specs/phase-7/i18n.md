# Phase 7 Internationalization (i18n)

> **Chrome:** Vietnamese primary, English secondary.  
> **Content:** Project prose language remains on `projects.language` (Phase 1) — i18n does not translate author prose.

---

## Scope split

| Layer | Locale source | Phase 7 action |
|-------|---------------|----------------|
| App chrome | User preference | Externalize all strings to message files |
| Domain labels | Same as chrome | Status pills, button labels, empty states |
| API error codes | Map code → message key | `errors.not_found` etc. |
| Bible / chapter prose | `project.language` | **No translation** — author content as stored |
| Bible metadata IDs | English identifiers | Unchanged (`rules.cultivation.realm`) |

---

## Default locale

| Setting | Value |
|---------|-------|
| Default chrome locale | `vi` |
| Fallback | `vi` → key missing → show key in dev, English string in prod optional |
| Supported chrome locales | `vi`, `en` |

First visit: detect `navigator.language` — if starts with `en`, offer EN; else VI. User override persists.

---

## Persistence (client-only)

| Key | Storage | Values |
|-----|---------|--------|
| `storyforge.locale` | `localStorage` | `vi` \| `en` |
| `sf_locale` | Cookie (optional SSR) | Same; 1 year max-age |

**No Phase 7 API** for locale. See [openapi.yaml](./openapi.yaml).

## File layout

```
apps/web/
  messages/
    vi.json          # Primary — complete
    en.json          # Secondary — complete for chrome
  lib/i18n/
    config.ts        # defaultLocale, locales[]
    get-messages.ts  # load JSON by locale
    use-translations.ts  # client hook
  app/
    layout.tsx       # LocaleProvider + lang attribute
```

```json

    "retry": "Thử lại",

    "title": "Dự án của tôi",

  },
  "chapter": {
    "status": {
      "drafting": "Đang viết",
      "locked": "Bị khóa"
    }
  },
  "continuity": {

  }

```

`en.json` mirrors keys; English copy for chrome.

## Usage rules

1. **No hard-coded user-facing chrome** in components — use `t('dashboard.title')` or server `getTranslations`.
2. **Identifiers in English** — component names, routes, API fields unchanged.
3. **Interpolation** — `"filteredEmpty": "Không có kết quả cho '{query}'"` with `{ query }` param.
4. **Pluralization** — use ICU or simple split keys (`inboxCount_one`, `inboxCount_other`) for VI/EN rules.
5. **Dates/numbers** — `Intl.DateTimeFormat(locale)` / `Intl.NumberFormat(locale)`.
6. **VI typography** — standard sans stack; no special font required.

## Locale switcher UI

| Location | Control |
|----------|---------|
| App header | `VI | EN` toggle or dropdown |
| Settings (optional) | Same control duplicated |

On change: update provider state, persist storage, set `<html lang="vi|en">`, no full reload.

---

## Migration checklist (implementation)

1. Inventory hard-coded strings in `apps/web` (grep Vietnamese/English UI literals)
2. Extract to `messages/vi.json` first
3. Add `en.json` translations
4. Wire `LocaleProvider` at root layout
5. Replace literals screen-by-screen per [web-screens.md](./web-screens.md)
6. ESLint rule optional: flag JSX string literals in `components/` (warn)
